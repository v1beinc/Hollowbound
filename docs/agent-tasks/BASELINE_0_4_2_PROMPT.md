# Задание второму агенту: проверенная simulation baseline для 0.4.2

Ты — второй инженер в общей рабочей директории — корне репозитория Hollowbound.
Выполни одну большую задачу: подготовь проверенную baseline текущего ядра
симуляции для следующей переносимой alpha. Главный агент отвечает за интеграцию
и итоговое качество; он параллельно реализует version/build stamp.

## Контекст и цель

Сначала прочитай `AGENTS.md`, актуальный верх `CHECKPOINT.md`, затем `VISION.md`,
`ROADMAP.md`, `TECH_STACK.md` и нужные разделы `RELEASE_PLAN.md`.
Новая логика — автономная AI-цивилизация: производство, организации, обмен,
коллективные знания, фоновое развитие, макроуправление. Это план будущих систем.
Текущая база — 0.4.1-prealpha, snapshot v24, analytics schema v5.
Сейчас выполняем gate 0.4.2; промышленный контур 0.5 ещё не начинаем.

Результат задачи: ревью существующего simulation diff, устранение подтверждённых
регрессий в пределах этого diff, свежие Release-проверки и честный отчёт.

## Разделение владения

- Твои изменения: только необходимые файлы `Simulation/` и новый отчёт
  `docs/validation/BASELINE_0_4_2.md`.
- Главный агент владеет `BuildInfo.cs`, `Program.cs`, `Game1.cs`,
  `Hollowbound.csproj`, `README.md`, `CHECKPOINT.md`, `CHANGELOG.md` и release docs.
  Не редактируй их; сообщи главному агенту, если потребуются изменения.
- Рабочая директория общая. До первого build согласуй с главным агентом момент
  окончания его правок. Не запускай конкурирующие build/test/benchmark процессы.
- Не создавай других агентов. Не делай commit/push/tag, reset/checkout/clean,
  не трогай `saves/`, не добавляй зависимости, потоки или новые игровые системы.

## Выполнение

1. Назови цель, scope и критерий готовности. Сними `git diff --stat` и изучи
   текущие изменения питания, резервов и pathfinding. Сохрани исходный список
   изменённых файлов в отчёте, отделив его от своих дальнейших исправлений.
2. Проверь реальные риски: доступность еды через стены, освобождение резервов
   при смерти/смене задачи/неудаче пути, save/load continuation, bounded cache,
   обновление индекса при исчерпании ресурсов. Сопоставляй код и regression cases.
   Исправляй только воспроизводимые или однозначно доказанные ошибки; для
   поведенческого исправления добавь предметный regression. Не делай rewrite
   и не оптимизируй по предположению. Если ошибки не найдены, так и напиши.
3. После синхронизации с главным агентом выполни последовательно:
   `dotnet build Hollowbound.sln -c Release -v minimal`,
   `dotnet run --project Hollowbound.csproj -c Release --no-build -- --self-test all`,
   `dotnet run --project Hollowbound.csproj -c Release --no-build -- --test-camera-layout`.
   Проверь exit code каждой команды. Исправь относящиеся к scope сбои, затем
   повтори затронутые проверки; полный финальный прогон должен относиться к
   окончательному simulation-коду.
4. Получи воспроизводимый headless baseline: один прогревочный запуск, затем
   три последовательных запуска `--benchmark 12345 4000 500 300` в Release
   через `--no-build`. Запиши каждый TPS, итоговую population/deaths, длительность,
   распределение/пределы и условия. Если это слишком долго из-за конкретного
   технического препятствия, сохрани выполненные результаты и точную причину.
   Не заявляй before/after ускорение без сопоставимой исходной серии.
5. В `docs/validation/BASELINE_0_4_2.md` запиши дату, HEAD, dirty state,
   версии контрактов, рассмотренный scope, найденные ошибки/исправления,
   точные команды/exit codes/результаты, baseline и оставшиеся gate.
   GUI FPS, ручная сессия, чистая машина, ZIP и feedback считаются непроверенными,
   пока не выполнены соответствующие реальные проверки. GUI не запускай в
   этой задаче. Не объявляй 0.4.2 выпущенной или полностью готовой.

После 8–12 действий дай короткий checkpoint: подтверждено / изменено / осталось.
После проверок заверши эту фазу без расширения задачи.

## Передача результата

Сообщи главному агенту: изменённые тобой файлы, предметные причины исправлений,
выполненные команды и результаты, путь отчёта, риски и непроверенные gate.
Итоговое ревью и интеграцию выполняет главный агент.
